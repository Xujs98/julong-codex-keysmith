# v0.2.8 验证记录

日期：2026-09-17。主机：macOS x86_64。修改前提交：`c90fc61`。

## 行为变化

配置管理的“还原配置”此前还原全部环境部署，并无条件调用 Codex 配置还原。现在前端提交当前已保存的勾选 ID，后端校验选择、按部署清单里的原始目录筛选文件，只还原选中客户端；剩余部署记录和备份继续保留。Codex 传输配置仅在 Codex 被选中时还原。CLI `environment restore` 共用同一实现。供应商页的 Codex 清理入口也不再连带还原其它客户端。

停止代理后允许取消勾选已部署的 Codex，同时保留其尚未还原的传输目录定位；仅有原生指令文件的旧部署不会阻止采用新配置目录。还原不依赖当前模型指令选择。

## 已验证

- Rust：41 项单元测试、9 项集成测试全部通过。独立的原生 Codex 会话测试默认忽略，本次未重复运行，因为没有修改启用协议。
- 六个客户端各自单独还原：选中客户端恢复原始文件，其余五个目录逐文件字节保持一致，包括 Codex 认证、配置和备份。部分还原后清单仍保存其它五个客户端；随后可还原全部剩余项。
- 重复还原不改变剩余部署清单；空选择、未知/重复 ID、前后端选择不一致均在写入前拒绝。
- 多选中的任一环境文件发生外部修改时，全部选中项保持原状；未选中客户端的外部修改不阻止其它客户端还原。
- 修改但未部署的新目录保持原状，实际还原部署记录中的旧目录。存在未完成环境事务时拒绝按选择还原，要求先恢复事务。
- 浏览器使用隔离 IPC fixture 验证真实前端按钮：只选 Claude 时发送 `["claude"]`；选 Grok 和 Gemini 时发送 `["grok","gemini"]`；全部取消勾选时显示提示且不再提交还原。还原后卡片状态刷新，按钮恢复可用。此项验证界面参数及交互，文件还原由上述 Rust 测试验证。
- 前端两个 JS 文件语法、Rust 格式、Tauri JSON、macOS/Windows shell 构建脚本语法和 Git diff 格式检查通过；所有应用版本字段更新为 0.2.8。
- Windows `cargo check --manifest-path src-tauri/Cargo.toml --target x86_64-pc-windows-msvc --tests` 通过，包含新增还原测试的编译检查。
- 测试使用独立临时目录。真实客户端配置、认证、中转地址和部署清单的 SHA-256 在最终测试检查中保持一致。

## 范围

还原仅覆盖矩龙部署时备份/管理的文件；其它客户端由用户手动配置的 API 地址与认证不属于矩龙备份。原生文件还原和 Codex 原有传输还原各自采用事务；如果原生文件已还原而后续 Codex 传输还原失败，界面明确显示完成部分与错误，可处理后重试。

未重新打包或替换已安装 App，未在 Windows 运行安装包，未停止本机现有代理。更新构建后重启应用才能使用新行为。
